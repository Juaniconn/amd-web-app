# ADR-025 — Producción basada en Órdenes de Producción

## Estado

Aceptada

## Fecha

2026-08-13

## Contexto

AMD Operations requiere trazabilidad desde RFQ hasta entrega.

Hoy el sistema cubre:

- CRM (cliente / contacto)
- RFQ (`quotes`; la solicitud es el estado `borrador`, ADR-024)
- Conversión de cotización `aprobada` a pedido mínimo `orders` (ADR-023)

No existe orden de producción. Convertir una RFQ **no** crea OP, no asigna máquina y no reserva material. Dirección no puede responder «qué estamos fabricando».

BUSINESS_SPEC §41:

- Regla 1: una cotización aprobada puede convertirse en pedido.
- Regla 2: un pedido puede generar una o varias órdenes de producción.

## Decisión

Toda RFQ **aprobada y convertida** genera una o varias Órdenes de Producción.

Cadena de trazabilidad:

```
CRM (cliente)
    → RFQ / cotización (quotes)
        → Pedido comercial mínimo (orders)     ← ya existe al convertir
            → Orden de Producción               ← Fase 4; no existe aún
                → Calidad
                    → Entrega
```

Reglas concretas para la implementación (aún no hay código):

1. El disparador es la cotización `convertida` (acción ya existente `convertQuoteToOrder`). No se crea OP desde `aprobada` sin conversión: la conversión es el compromiso comercial.
2. La OP referencia `orders.id` (y, por esa vía, `quotes.id` y `customers.id`). No se omite el pedido mínimo ya persistido.
3. Un pedido puede generar **una o varias** OP (Regla 2): una por partida o por ruta, según lo defina Producción. No se asume 1 RFQ = 1 OP.
4. La OP es la entidad de piso: estados, centro de trabajo, máquina, operador, tiempos, material requerido.
5. Fase 4 **no** construye `/orders` completo, inventario, compras, calidad ni entregas.

## Alternativas consideradas

- Generar OP directo desde `quotes` sin `orders`: rechazado. Rompería ADR-023, la numeración `AMD-YYYY-NNNNN` y la Regla 2.
- Crear OP automáticamente en el mismo instante de `convertQuoteToOrder` sin diseño de estados/centros: rechazado. Adelantaría implementación sin el modelo de Fase 4.
- Esperar la UI de Pedidos antes de Producción: rechazado por Dirección (ADR-026). El pedido mínimo ya es la puente comercial.

## Razón

Permite trazabilidad completa de fabricación sin inventar un segundo documento comercial y sin saltarse el pedido que Fase 3 ya persiste.

## Impacto

- CRM → RFQ → Producción → Calidad → Entrega queda como flujo de negocio objetivo.
- El módulo Producción consume `orders` / `order_items` (cliente, partidas, cantidades, número de parte).
- Inventario y Compras no bloquean el diseño de la OP, pero la OP quedará en `Esperando Material` cuando esas fases existan y falte stock.
- `/production` y permisos `production:*` deberán crearse en la implementación; hoy no existen.

## Consecuencias

- Trazabilidad completa de fabricación cuando Fase 4 esté implementada.
- Migraciones futuras crearán `production_orders` (y, si aplica, operaciones / centros / máquinas) con FK a `orders`.
- Ampliar `convertQuoteToOrder` para emitir OP es un cambio de Fase 4, no de esta preparación documental.
- Calidad (Fase 7) e Entregas (Fase 8) dependen de la OP, no de la cotización.
