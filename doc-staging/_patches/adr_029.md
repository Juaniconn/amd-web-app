# ADR-029 — Permisos operativos de producción vía usuarios y roles

## Estado

Aceptada

## Fecha

2026-08-13

## Contexto

Fase 1 ya tiene usuarios, roles y permisos (Better Auth + RBAC, ADR-007/008). El rol Producción solo tiene `dashboard:read`. Dirección no quiere responsables «de planta» hardcodeados ni personas concretas en la spec.

## Decisión

Los permisos operativos de piso se asignan **a roles**, y los roles **a usuarios registrados**. No se asumen personas.

Permisos principales a introducir en implementación (nombres de negocio; IDs exactos al implementar):

| Permiso | Intención |
|---|---|
| Autorizar Producción | Liberar OP a piso (`Pendiente` → `Liberada`) |
| Liberar Material | Entregar/reservar insumo a la OP (Inventario Fase 5) |
| Programar Máquinas | Centro, máquina, operador, ventana (`Programada`) |
| Liberar Calidad | Inspección OK → `Terminada` |
| Cerrar Orden | Cierre de piso / paso a entrega (`Entregada` o equivalente) |

El **responsable** de una máquina o de una OP es un `users.id`, no un string.

Mapa rol→permiso de planta (Gerente vs Supervisor vs Inspector) queda en [[Pendiente Validacion Direccion]]; no se congela aquí.

Administrar el catálogo de máquinas (ADR-027) es un permiso de **configuración**, distinto de estos cinco. Lo ejerce Administrador salvo que Dirección amplíe.

## Alternativas consideradas

- Botones sin `requirePermission`: rechazado (ADR-008).
- Un permiso único `production:write`: rechazado; mezcla autorización, programa, calidad y cierre.
- Puestos fijos «Juan programa»: rechazado.

## Razón

Reutiliza el RBAC de Fase 1. Separar los cinco actos evita que un operador de CNC libere calidad o cierre la orden.

## Impacto

`src/lib/permissions/catalog.ts` deberá extenderse en la implementación. Hoy **no** se modifica (esta entrega es solo documentación). Pages y Server Actions de producción usarán `requirePermission` como CRM/RFQ.

## Consecuencias

[[Operadores y Roles]] describe puestos de planta como guía, no como `role_id` nuevos obligatorios. Dirección puede cubrir varios permisos con el rol Producción o partir roles; eso se valida aparte.
